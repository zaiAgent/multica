# 对比两软件的差异：Multica × MiraSim

> 结论先行：**两者是"多智能体协作光谱"的两端，不是替代关系。**
> Multica（multica-ai/multica，自部署开源自托管）以**任务/组织为中心**；MiraSim（mirasim.ai）以**会话为中心**。
> 本对比基于 Multica 实际代码库（本仓库）与 MiraSim 官方文档（见《mirasim软件架构原理与说明.md》附录 B 的来源清单）。

## 1. 十五维度总览表

| # | 维度 | Multica | MiraSim |
|---|---|---|---|
| 1 | 中心抽象 | Workspace/Issue（任务派发） | Session（会话驻留） |
| 2 | 工作流 | 看板列交接（一列一目标，两跳路由） | 队列 + 四种轮内干预 |
| 3 | 执行单元 | Run（八态状态机，daemon 15s 心跳） | 会话步（step，轮内可打断） |
| 4 | 并行模型 | 组织并行（Issue 拆给智能体/小队/成员） | 文件并行（worktree-per-session） |
| 5 | 人在环路 | 轮外：Run 交付后人工审核（in_review 列） | 轮内：steer/jump 即时干预 |
| 6 | 智能体间通信 | 无直接通道（经看板列交接与评论） | 会话互联协议（五工具 + 三重熔断 + jsonl 账本） |
| 7 | 质量验收 | 人工审核（人移动看板列） | 模拟用户 eval（结构化 DOM 断言） |
| 8 | 成本观测 | 订阅/席位级 | 五维账本（智能体/模型/账号/工作区/会话）到单次调用 |
| 9 | 历史回溯 | 评论时间线 + transcript 查看 | ForkFromTurn / ReplayTurn / RollbackTurn |
| 10 | 配置层级 | 工作区级（服务端存储） | 项目级 `.mirasim` 随仓库提交 |
| 11 | 交付物形态 | git 分支 + PR + 评论 | worktree 合并/放弃由 Verdict 决定 |
| 12 | 集成 | 飞书/自托管 webhook 等 | MCP + 内置技能 |
| 13 | 部署 | 自托管（Docker Compose），数据自持 | 本机 Workbench（免费）/ Cloud（付费） |
| 14 | 计费逻辑 | 自托管无平台费 | 自有账号 / 自带 key / 平台额度三模式 |
| 15 | 目标用户 | 要"组织工作流"的团队 | 要"个人/小组并行生产力"的开发者 |

## 2. 五个本质差异

### 差异一：任务中心 vs 会话中心

- **Multica**：Issue 是承诺的最小单元。一列一目标，Run 结束交付，人验收，走组织流程。
- **MiraSim**：会话是驻留的工作单元。指令源源不断进出，人随时插入，任务只是会话的产物之一。
- **本质**：Multica 管的是**组织协作契约**，MiraSim 管的是**个体工作流连续性**。

### 差异二：轮外状态机 vs 轮内干预

- **Multica**：Run 是八态状态机（queued/dispatched/running/…），daemon 15 秒心跳，人只能在 Run **结束后**审核；
- **MiraSim**：steer 不打断下一步生效、jump 立即打断、recall 撤回排队指令——干预延迟以"步"计。
- **本质**：错误发现成本完全不同。轮内纠偏省掉的是"整轮白跑再重来"。

### 差异三：组织并行 vs 文件并行

- **Multica**：并行靠把 Issue 交给不同智能体/小队/成员（分工维度）；
- **MiraSim**：并行靠 git worktree 让多会话**同时写同一份代码**（物理维度）。
- **本质**：正交的两种并行。Multica 没有 worktree 级并行；MiraSim 没有组织级工作流。

### 差异四：人工验收 vs 自动验收

- **Multica**：质量门是人（in_review 列人工审核，看板拖动放行）；
- **MiraSim**：模拟用户 eval 读 DOM 做结构化断言，自动验收。
- **本质**：验收瓶颈在人 vs 在机器。前者更稳但慢，后者快但只能验"可形式化"的部分。

### 差异五：自托管 vs 本机+云端

- **Multica**：自托管（Docker Compose），数据与密钥完全自持，无平台依赖；
- **MiraSim**：本机 Workbench 免费层 + 云端付费层，官方托管运营。
- **本质**：信任边界与成本结构不同。企业合规场景倾向前者，个人效率场景倾向后者。

## 3. 交叉观察：各自的长短板

**Multica 的长板**恰是 MiraSim 的短板：组织级工作流治理（看板列交接、审批放行、审计时间线）、自托管数据主权、飞书等企业集成。

**MiraSim 的长板**恰是 Multica 的短板：轮内干预、worktree 文件并行、单次调用级成本账本、自动验收 eval、会话历史回放、项目级配置随仓库走。

**结论**：非替代关系。Multica 是"把智能体纳入组织流程"的底座，MiraSim 是"把个人并行生产力拉满"的工具。Multica 团队若吸收 MiraSim 机制，方向应当是**在自己不变的组织骨架上，补齐轮内干预、细粒度成本与自动验收**——具体见《multica如何参考mirasim去完善，改进建议.md》（MS-01~MS-08）。
