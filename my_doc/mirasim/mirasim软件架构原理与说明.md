# MiraSim 软件架构原理与说明

> 依据 MiraSim 官方文档中文版（mirasim.ai/docs/zh/）的快速上手、核心概念、并行会话、排队与引导、分支与 worktree、会话互联、Skills/MCP/工具、用量与成本共八章原文整理；辅以社区资料（mirasim.wiki、第三方收录页）交叉核对。
> 信息快照：2026-11。文中凡来自社区资料而非官方文档的表述，均已单独标注来源。

## 1. 产品定位

MiraSim 是一个**编程智能体平台**（One Agent IDE）：把"写代码的智能体"和"替你测试的模拟用户"装进同一个工作台。官方口号"Build anything with anyone. At 100x throughput."，中文语境的宣传语为"更快更省、无限并发协同、零损耗"。

核心主张有三条：

1. **统一运行**：Claude Code、Codex、OpenCode 等多种 CLI 编程智能体在一个平台里统一安装、统一配置额度、统一调度；
2. **并行吞吐**：多个会话（智能体实例）在窗格分组中同时运行，互不干扰，每个会话可各占一个 Git worktree，实现同仓库文件级并行；
3. **验收闭环**：内置 `eval` 能力，让"模拟用户"从真实入口把做好的东西试用一遍，截图与每步记录留在本机（官方 Skills 文档确认此技能存在）。

产品阶段：官方文档未提邀请码机制，社区资料称其为邀请制内测、Alpha 阶段（来源：mirasim.wiki，2026-10 快照）。

## 2. 总体架构：三层模型

官方"核心概念"章给出明确的三层架构：

| 层 | 性质 | 内容 | 计费 |
|---|---|---|---|
| **Workbench（工作台）** | 本机，桌面应用 | 多智能体在窗格与分组中并行运行；会话共用项目目录或各占 worktree；文件、diff、终端、Git、产物都在会话旁边；手机 App 跟进会话 | 免费 |
| **Team（团队）** | 功能层 | 频道、话题、评论、产物批注，每轮标明发起人；在协作空间、设为协作空间的电脑、共享账号上可用 | 不单独收费 |
| **Cloud（云端）** | 付费主机层 | Linux/Mac 协作空间，合上笔记本也照常运行；每空间 5 个协作席位（可加购）+ 100 观察位；团队可共享空间额度与 API key | 付费 |

注意其架构取向：**三层是"运行位置 + 协作范围"的分法，而非微服务分层**。Workbench 是免费本机层，云端只是"把 host 挪到别人机器上"，团队协作功能横贯两层。

## 3. 核心概念模型

### 3.1 Host（服务端）

Host 是运行智能体、保存项目文件、Git worktree、会话历史、产物和定时任务的地方。**通常就是用户自己的电脑，由桌面应用启动**；也可改为连接自行部署的 macOS/Linux 服务器；协作空间和"设为协作空间的电脑"同样是 host。界面上每个 host 表现为一个"空间"（space），在左栏顶部空间菜单切换。

切换空间 ≠ 数据迁移：手机配对与定时任务留在原 host。这一细节体现了**"host 是状态锚点"**的设计。

### 3.2 Workspace（工作区）

工作区就是添加进来的一个目录。侧栏列出所有已添加目录；会话若在未添加的目录里启动，该目录自动入列。**目录即工作区，无额外建库概念。**

### 3.3 Session（会话）——最小执行单元

一个会话 = 与一个智能体的一次对话，绑定五元组：

| 维度 | 说明 |
|---|---|
| 智能体 | Claude Code / Codex / 其他已装智能体，按会话选择；账号按智能体全局生效 |
| 模型 + 推理强度 | 按会话从订阅模型与自配模型中选 |
| 工作区 + 基准分支 | 运行目录 + 起始分支 |
| worktree（可选） | 会话跑在独立分支的 Git worktree 检出中 |
| Transcript（对话记录） | 每轮对话、推理过程、工具调用、子任务、计划、决策——可检索、可分叉、可导出 |

每个会话拥有**独立的智能体进程、对话记录、指令队列和终端**；发送按钮旁的圆环实时显示上下文窗口占用，占满时对话自动压缩（概括腾出空间），也可手动 `/compact`。

会话状态独立显示：运行中、等待处理、已停滞、已完成、已失败；另可打工作流标签（收件箱、进行中、待审查、已完成、暂存）。

### 3.4 界面嵌套：Group / Tile / Document Stack

工作台三层嵌套：**分组**（一整套布局，可在多个分组同时出现同一会话，关闭分组只关视图、会话继续跑）→ **分格**（会话/终端/文档各占一格）→ **文档标签**（只有文档可叠标签，会话与终端永不叠放，保证"打开文件不遮住智能体"）。

### 3.5 Artifact（产物）

构建结果、截图、日志、导出文件、评测报告保存在产出它们的 host 上，可在会话旁预览、定位到文件系统或下载。

### 3.6 磁盘布局

```
~/.mirasim                 # host 状态：settings.json、会话记录、本机用量数据
<workspace>/.mirasim       # 项目级配置，可随仓库提交：工作区技能 + schedules.json
```

**项目级配置随仓库走**（技能、定时任务用 JSON 提交进版本库）是其后文多个机制的基础。

## 4. 并行机制

MiraSim 的并行不靠编排器，靠**三个正交机制叠加**：

1. **窗格分组（视图并行）**：多个会话同屏并跑，切换分组不中断会话；
2. **worktree（文件并行）**：会话勾选 worktree 后运行于独立分支的检出上，同一仓库并行的智能体互不改文件；`git status`/`git diff`/编辑器照常可用，合入成果就是一次普通合并，放弃即删分支。删除会话可连带删除 worktree，有未提交改动时 Git 拒绝删除（安全闸）；
3. **会话互联（通信并行）**：见第 6 节。

## 5. 排队与引导：运行中的干预语义

每会话独立指令队列。一轮执行中发消息时，有四种动作语义：

| 动作 | 对当前轮影响 | 语义 |
|---|---|---|
| 发送（send） | 无 | 排到队尾，本轮结束后执行 |
| 引导（steer） | 无打断 | 交给正在执行的一轮，在下一步生效，记录中标注为引导 |
| 插队（jump） | **打断当前轮** | 该指令紧接着执行 |
| 撤回（recall）/移动（move） | 无 | 队列内取回编辑 / 拖动排序 |

**配置锁定原则**：排队指令锁定发送时刻的模型与推理强度，之后改配置只影响后续指令。

全部队列操作均有 ui-cli 等价命令（`mirasim ui-cli --port 4970 queue steer/jump/recall/move --session KEY --ref R`），即可脚本化操纵运行中的会话。

## 6. 会话互联协议

这是 MiraSim 最具工程参考价值的子系统。会话默认互相隔离；在指令里 `@` 点名另一会话时，两端**就地自动开启互联**；智能体用 `start_session` 新建会话亦自动互联。未互联的会话不出现在别人的列表里、收不到消息。

### 6.1 智能体获得的五个工具

| 工具 | 能力 |
|---|---|
| `list_sessions` | 列出已互联会话及状态（可跨工作区/空间/电脑） |
| `read_session` | 读对方最近四轮摘要（≤2KB）+ 运行状态；可等待其本轮结束（5 分钟超时） |
| `send_session_message` | 发消息，单条 ≤8KB，返回投递结果 |
| `read_session_message` | 按消息 id 取回完整原文 |
| `start_session` | 新建会话（指定智能体/模型/强度/开场任务），不阻塞，回信以消息返回 |

### 6.2 投递语义（按目标状态分派）

| 目标状态 | 投递结果 |
|---|---|
| 空闲/上轮已结束 | 立刻起新一轮，消息即输入 |
| 运行中且该智能体支持中途输入 | 进入当前轮，下一步被读到，不打断进行中的工具调用 |
| 运行中但不支持中途输入 / 等人回答 | 暂存到轮次边界投递，最多等 5 分钟，超时过期并提示 |
| 未开互联 | 拒绝投递 |
| 终端会话 | 可读不可发 |

### 6.3 三重熔断防护（防智能体互发失控）

1. **发送频次**：单会话连发 30 条后，每 2 秒恢复 1 条额度；30 秒内向同一会话重复相同文本直接丢弃；
2. **链深熔断**：一条消息引发的接力最多 24 跳，有真人参与即重置计数；
3. **乒乓熔断**：两会话 5 分钟内互发超 12 条且双方均无真人输入 → 该"对"被熔断并界面可见。

### 6.4 本地消息账本

每条消息（谁发给谁、原文、投递结果）记录于 `~/.mirasim/messages/`，按月 jsonl 分文件，保留 90 天，**不上传**。

## 7. 分支、重跑与回退

- **分叉**：任意一条回复可作新分支起点，分支继承截至该处的完整历史，原会话不受影响继续运行；分支标注来源会话与轮次，母会话列出全部分支。智能体不支持分叉时直接提示；
- **重跑**：按该轮原智能体/模型/强度把同一问题再问一次；重跑较早轮会丢弃其后各轮（菜单注明）；
- **回退**：消息级操作，可选择恢复对话、代码或两者到发送前，消息放回输入框可改后重发。

这套能力把 **transcript 当成一等可编辑资产**：可检索、可分叉、可导出、可回退，而不是只读日志。

## 8. Skills、MCP 与工具体系

- **技能**：命名可复用的说明（测试方法、部署流程等），智能体按需自行加载。**全局技能**（设置›插件›技能，全机可用）与**项目级技能**（`<workspace>/.mirasim`，随仓库走）两级；输入 `/` 列出全部技能与智能体自带命令；
- **MCP 服务**：设置›插件›连接器中添加，或终端命令管理；带 `health` 存活探测；
- **连接器**：基于 MCP 的精选目录，可按智能体分别启用、配置凭据、远端运行、OAuth 重授权、对照真实服务校验（记录工具数/错误）；`connectors search` 查询官方 MCP 注册表；
- **CLI 工具自动检测**：列出 PATH 上常见开发工具（git、gh、docker 等）及其登录态；
- **六个内置技能**（随应用更新，用户改过的保留）：`mirasim-guide`（官方文档问答）、`mirasim-operate`（在 MiraSim 里办事：改设置、开会话、定时任务、操作别的空间）、`mirasim-publish`（对外发布）、`mirasim-doc`（写文档进空间）、`mirasim-needs-you`（需登录/确认时停下并把链接交给人）、**`eval`**（点名运行：从真实入口把成品试用一遍，截图与每步记录留在本机）。

## 9. 计费与成本模型

**三种付费模式**（每会话用其一、随时切换、同空间可并用）：

| 模式 | 费用 |
|---|---|
| 自有账号（Claude/ChatGPT 等订阅登录） | 计入用户订阅，MiraSim 不另收费 |
| 自带 API key（任意供应商或中转，可空间内共享） | 供应商按 key 结算 |
| 平台额度（个人或空间额度） | 1 额度按官方 API 价计 $1，所有模型通用 |

团队成员不必各备账号：所有者把额度转入空间或共享一把 key，全队即可开工。

**流量监控账本**（设置›流量监控）：每次模型调用入账，含 token、缓存命中、成本估算；按今天/7/30/90 天/自定义范围统计，与上一周期对比；趋势图按类型、智能体、模型下钻；**分摊表按智能体、模型、账号、工作区、会话五个维度**给出 token 占比、调用次数、输入/输出、缓存读取、命中率、成本估算、最近活动；可下钻到**单次调用**（推理 token、耗时、状态）；支持 CSV 导出与 `mirasim ui-cli traffic` 脚本读取。

这是把"可观测性"做到调用粒度的完整账本设计。

## 10. Computer Use 与模拟用户

- 官方文档设有独立章节（第 19 章 Computer Use），quickstart 交叉引用确认该能力存在；
- 社区资料（mirasim.wiki、fly63 收录页）补充的口径：Computer Use 与模拟用户功能消耗平台额度（或自备 key），其余功能免费账号可用；智能体直接**读取页面结构而非截图识别**——约 184B 对比截图 60KB，传输量差约 330 倍，驱动真实 Chrome 与真实用户配置；iOS/Android 模拟器以同样方式响应，移动端产品亦可被模拟用户测试（来源：mirasim.wiki 引官方数据，本报告未直接核验官方原文）；
- 官方"Research notes"引用两篇论文作为模拟用户的理论依据：Generative Agents（Park et al., 2023，记忆-反思-规划涌现社会行为）与 Voyager（Wang et al., 2023，技能库自我改进智能体）（来源：mirasim.wiki 转引，原文在 mirasim.ai/blog）。

## 11. 其他形态与平台支持

- **TUI ⇄ GUI**：空会话可开 TUI，应用附带 `mirasim` 命令行；`ui-cli` 可脚本化操纵（队列、技能、MCP、连接器、流量账本等，均有子命令）；
- **手机 App**：Android 直装、iOS 经 TestFlight（官方 quickstart 确认）；手机可跟进会话；
- **桌面平台**：官方 quickstart 明确支持 macOS 13+（Apple Silicon/Intel 分包）、Windows 10 1809+、Linux（AppImage 或 Ubuntu 22.04 同代 .deb）。（社区 wiki 早期称"仅 Apple Silicon 无 Windows 版"，与当前官方文档不一致，以官方为准）；
- **数据与隐私要点**：会话记录与用量数据存 `~/.mirasim`（本机）；消息账本本地保留 90 天不上传；项目配置随仓库提交（来源：核心概念章）。

## 12. 架构设计原则提炼

| # | 原则 | 在 MiraSim 中的体现 |
|---|---|---|
| 1 | **本机优先，云端可选** | host 默认是用户电脑，云端只是换 host；本地数据不上传 |
| 2 | **会话为最小并行单元** | 进程/队列/记录/终端/上下文窗口全会话独立 |
| 3 | **transcript 一等公民** | 可检索、分叉、重跑、回退、导出 |
| 4 | **文件并行靠 Git 原生** | worktree 即隔离，合并/放弃即普通 Git 操作 |
| 5 | **通信要带熔断** | 频次、链深、乒乓三重防护 + 全量本地账本 |
| 6 | **上下文是最贵的资源** | 结构化读取浏览器（省 330 倍传输）、单工具入口（1k vs 53k token，社区口径）、自动压缩 |
| 7 | **成本可观测到调用粒度** | 五维分摊 + 单次调用明细 + CSV/脚本出口 |
| 8 | **项目配置随仓库走** | `<workspace>/.mirasim`：技能与 schedules.json 可提交 |
| 9 | **人始终在环** | 引导不打断、插队才打断、needs-you 停下交链接、乒乓熔断需真人重置 |
