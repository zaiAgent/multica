## 1. 一句话定位

- **MiraSim**：给开发者个人/小团队的"One Agent IDE"——把多个 CLI 编程智能体装进一个本机工作台，并行驾驶、即时干预、模拟用户验收。**它是"驾驶舱"。**
- **Multica**：多智能体协作工作台——Workspace/Issue/Agent/Squad/Run 的组织化模型 + 看板列交接工作流 + Autopilot 持续运行，面向团队把任务流水线化。**它是"流水线"。**

一句话概括差异：**MiraSim 以"会话"为中心、以人的实时操纵为节拍器；Multica 以"任务"为中心、以状态机和交接规则为节拍器。**

## 3. 五个本质差异展开

### 3.1 会话中心 vs 任务中心

MiraSim 的世界是一排排**活着的会话**：状态机就五种（运行中/等待处理/停滞/完成/失败）+ 人工标签（收件箱/进行中/待审查/完成/暂存）。人看着一屏会话，像看一排仪表。

Multica 的世界是**任务的管线**：Issue 在看板列间被交接，Run 有八态状态机严格托管，Squad 是组织而非屏幕。人看的是一张看板。

由此派生一串差异：MiraSim 需要"窗格不遮会话"这种交互细节（文档专门强调"打开文件不会遮住智能体"），Multica 需要"列交接目标与两跳路由"这种流程语义。

### 3.2 即时干预 vs 状态机托管

这是运行时哲学的分岔。MiraSim 干预是**轮内**的：steer 在不打断工具调用的前提下把话递进正在执行的一轮；jump 才打断；recall 把排队指令取回输入框。配合"配置锁定"（排队指令锁定发送时的模型与强度），干预语义完整且可预期。

Multica 干预是**轮外**的：Run 进入状态机后，人的主要动作是等待状态迁移或整跑重试。Autopilot 提供自动派单，但没有"在 Run 中途塞一句话"的能力。

### 3.3 文件级并行 vs 组织级并行

MiraSim 并行的隔离单位是**Git worktree**：同仓库多智能体互不碰文件，合并即普通 Git 合并，放弃即删分支，"有未提交改动时 Git 拒删"是安全闸。它不解决"谁先做哪个任务"——人自己排。

Multica 并行的隔离单位是**Workspace 与看板列**：任务归 Issue，交接按列规则走。它解决"任务怎么流转"，但同仓库多智能体并行没有文件级隔离机制，存在改同一份代码的冲突风险。

两者互补：MiraSim 有"并行无冲突"，缺"任务流水线"；Multica 有"任务流水线"，缺"并行无冲突"。

### 3.4 验收自动化 vs 人工验收

MiraSim 把验收做成一个内置技能 `eval`：模拟用户从真实入口试用成品，截图与每步记录留在本机；配合结构化浏览器读取（读 DOM 结构而非截图，社区口径传输量差约 330 倍）与真实 Chrome/模拟器驱动。

Multica 的验收是看板列流转 + 人工检查，质量闭环依赖人（第 3 册 NG-F 已规划 CI 护航与复合质量门，但尚无"模拟用户"这一角色）。

### 3.5 本机免费 + 云端付费 vs 自托管

MiraSim 商业模式是"本机免费用、跑在你自己的模型账号上"，收费点是云端协作空间与平台额度（含 Computer Use/模拟用户消耗）；数据策略是本地优先、消息账本不上传。

Multica 是自托管开源：组织自持数据、自管部署面，无平台额度概念。对数据主权要求强的组织，Multica 的模式更稳。

## 4. 各自强项与短板

**MiraSim 强项**：并行驾驶体验（窗格/worktree/干预语义）；会话互联的工程化防护设计；成本账本到单次调用；模拟用户验收闭环；项目配置随仓库版本化。
**MiraSim 短板**：无声明式工作流与组织级看板，任务流水线要人盯着排；团队协作层较轻（频道/评论级）；云端协作空间有地域限制；无跨会话语义记忆；处于 Alpha 阶段（社区口径），成熟度待验证。

**Multica 强项**：组织化任务模型与 Autopilot 持续运行；看板 + 飞书/企业微信的组织内嵌；自托管数据主权；Run 状态机的失败恢复纪律（心跳/重连/重试）；11 种 CLI 集成面。
**Multica 短板**（与第 3 册诊断一致，此处从 MiraSim 镜像再确认）：无成本硬治理（对应 MiraSim 账本）；工作流单线无并行（对应 worktree）；无轮内干预（对应 steer/jump）；无统一智能体间通信防护与账本（对应互联协议）；无验收自动化（对应 eval）；上下文无观测与压缩管理（对应上下文环）。

## 5. 差异本质与启示

两者不是替代关系，是**光谱两端**：MiraSim 把"个人即时操纵的并行智能体"做到极致，Multica 把"组织托管的任务流水线"做到极致。Multica 的改进方向恰恰多是 MiraSim 已经验证过的"另一端"能力——这构成第三份文档《multica 如何参考 mirasim 去完善，改进建议》的全部内容。
