## 二、背景与任务目标

小组已将 Multica（多智能体协作工作台：Workspace / Issue / Agent / Squad / Runtime / Run / Autopilot / Skill 概念模型，daemon 本地执行 + CLI 集成 + 飞书集成，支持自托管）部署并进入试运行。当前缺的不是"能不能装"，而是对它的架构理解、与小组真实场景的适配判断，以及一套可执行的导入方案。

**本任务要求在 3 天内，以评估报告和实施方案的形式回答三个问题：**

1. **是什么** —— Multica 的架构与运行机制是什么，能力边界在哪里（能做什么 / 做不了什么）；
2. **合不合适** —— 与小组现有工作场景的匹配度如何，哪些场景值得导入、哪些不值得；
3. **怎么落** —— 如何分阶段把它导入小组日常工作：先在谁、在哪个场景试点，用什么工作流，用什么指标衡量效果。

> 任务成功定义：3 天后，小组对"是否导入、导什么、怎么导"三个问题形成有依据支撑的一致结论。

## 三、任务范围

**范围内**

- 架构研究：概念模型、Run 状态机与 daemon 心跳 / 重试机制、Workflows（看板列交接）模型、CLI 与飞书集成面、自托管部署面；
- 适配评估：选取小组 2–3 个真实工作场景逐一对照分析（流程匹配、改造成本、权限与数据安全、Token 成本可控性、失败恢复）；
- 导入推进：选定首个试点场景，设计试点工作流，制定分阶段导入计划与验收指标，完成一次小组评审。

**范围外**

- 不做 Multica 源码级二次开发，发现的能力缺口仅登记建议（可对接第 3 册变更登记清单的编号体系）；
- 不改动生产系统，实验一律在试运行环境进行；
- 不组织全组培训，本任务仅产出培训大纲要点。

## 七、执行注意事项

1. **以试运行环境为边界**：不触碰生产系统；涉及密钥 / 凭证的配置遵守小组安全规范。
2. **成本意识**：智能体长时间无人值守任务须设置预算上限，关注 Token 消耗（可参考第 1 册成本优化章节）。
3. **评估客观**：允许最终结论为"不导入 / 暂缓导入"，不为导入而导入；结论须能回溯到证据。
4. **区分现状与蓝图**：第 3 册 Multica-NG 属改进设想，评估基线以当前版本实际能力为准，勿将"未来会有"当作"现在就有"；确认的能力缺口记入建议清单，不自行二开。
5. **风险前置**：Day 2 末的方向确认是硬检查点，避免 Day 3 在错误方向上投入。
