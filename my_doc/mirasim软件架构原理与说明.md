# MiraSim 软件架构原理与说明

> 研究对象：MiraSim（mirasim.ai）——智能体并行工作台。
> 信息来源：官方文档 https://mirasim.ai/docs/zh/quickstart 及其子章节（sessions / queue / messaging / skills-tools / usage / branches），经 sitemap.xml 核实真实路径后抓取原文。
> 标注约定：未抓到原文的章节（Computer Use、automations、models、cloud-hosts、workbench）在本文中以「社区口径」单独标注，来自社区转述，未与官方原文核对。

## 1. 一句话定位

MiraSim 是一个**以"会话（Session）"为中心**的智能体并行工作台：把多个 CLI 编码智能体（Claude Code、Codex、Gemini CLI 等）装进同一个工作台，用队列与分支机制让它们并行干活、互相通信，并用成本账本与 eval 机制兜住质量与开销。

## 2. 三层产品架构

| 层 | 名称 | 部署形态 | 计费 | 适合 |
|---|---|---|---|---|
| 1 | Workbench | 本机运行 | 免费 | 个人开发者，单机并行 |
| 2 | Team | 自带协作层 | 按席位 | 小团队共享工作区 |
| 3 | Cloud | 云端托管 | 付费（平台额度） | 企业、跨地域协作 |

- 同一套核心（会话模型、排队、互联协议）贯穿三层，差异只在运行位置与账号体系。
- Workbench 免费、数据在本机；Cloud 提供云端空间运营（社区口径：官方对传输量有"330 倍"量级的压缩声明，未在原文核实）。

## 3. Session：五元组会话模型

一个会话 = 五个可变维度的组合：

**智能体 × 模型强度 × 工作区分支 × worktree × transcript**

1. **智能体**：Claude Code / Codex / Gemini CLI / 通用适配器等；
2. **模型强度**：同一智能体可挂不同档位的模型（强模型做规划、弱模型做执行）；
3. **工作区分支**：会话绑定某个 git 分支；
4. **worktree**：文件级并行的载体（见 §5）；
5. **transcript**：完整对话记录，可 Fork / Replay / Rollback（见 §7）。

会话不是"一次任务"，而是**可长期驻留、可干预、可回放的工作单元**——这是 MiraSim 与任务派发型工具的根本分野。

## 4. 排队与干预：send / steer / jump / recall

智能体忙不过来时，指令进入队列。四种干预动作：

| 动作 | 时机 | 语义 |
|---|---|---|
| send | 智能体空闲 | 直接送入下一轮 |
| steer | 智能体运行中 | **不打断**，注入后于下一步生效（软干预） |
| jump | 智能体运行中 | **打断**当前步，立即切到新指令（硬干预） |
| recall | 智能体运行中 | 召回/撤回排队中的指令 |

要点：干预是**轮内**的——不需要等任务结束，人在环路中的延迟以"步"为单位，而不是以"任务"为单位。

## 5. worktree：文件级并行

每个并行会话各持一个 git worktree：

- 同一仓库多个会话同时写文件互不踩踏；
- worktree 是临时载体：Verdict 决定合并回主分支或整体放弃；
- 与"组织级并行"（把任务拆给不同人/智能体）正交：worktree 解决的是**同一份代码上的物理并行**。

## 6. 会话互联协议

智能体之间可以互相发消息，协议三要素：

### 6.1 五个内置工具

投递、收取、广播、订阅、状态查询（名称以官方文档为准）——智能体在对话中调用，即完成一次跨会话通信。

### 6.2 投递语义表

每条消息明确：投递目标（会话/组）、投递时机（立即/空闲时）、是否要求回执。

### 6.3 三重熔断（防雪崩）

| 熔断 | 阈值 | 恢复 |
|---|---|---|
| 频次熔断 | 单会话 30 条消息 | 冷却 2 秒 |
| 链深熔断 | 转发链 24 跳 | 直接拒绝 |
| 乒乓熔断 | 两个会话互发 12 条 / 5 分钟 | 双向冷却 |

外加**本地 jsonl 消息账本**，保留 90 天，供事后审计"谁在何时对谁说了什么"。

## 7. Transcript 三操作：Fork / Replay / Rollback

- **ForkFromTurn**：从历史某一轮分叉出新会话（"如果当时走另一条路"）；
- **ReplayTurn**：重放某一轮；
- **RollbackTurn**：回滚到某一轮。
- 配合 §4 的干预动作，形成"时间旅行"式调试能力。

## 8. eval：模拟用户验收

- 内置**模拟用户（Simulated User）**：以结构化方式读取应用的 DOM，模拟真实用户做验收断言；
- 相当于给"智能体改完的代码"配一个自动化验收员，质量门由它把守。

## 9. 成本账本：五维分摊

每单次调用记：**智能体 × 模型 × 账号 × 工作区 × 会话** 五个维度；可下钻到单次调用明细，导出 CSV。

- 回答的问题："这个会话/这个智能体/这个模型今天花了多少钱？"
- 与三层计费模式（自有账号 / 自带 key / 平台额度）衔接。

## 10. Skills、MCP 与六个内置技能

- Skills 机制：把可复用流程封装为技能；项目级配置放在 `<workspace>/.mirasim`，**随仓库提交**，团队共享同一套技能与配置；
- MCP（Model Context Protocol）支持外接工具服务；
- 六个内置技能覆盖日常高频流程（官方文档 skills-tools 章节列举）。

## 11. 三种付费模式

1. **自有账号**：用户自己的模型账号，MiraSim 不抽成；
2. **自带 key**：API key 直连，按量结算；
3. **平台额度**：购买平台额度，平台代付。

## 12. 流量账本（社区口径）

Cloud 层对传输量有压缩与计量机制；社区口径称"330 倍传输量优化"，**未在官方原文核实**，仅作线索记录。

## 附录 A：架构九原则（本文提炼）

1. 会话是中心，任务是会话的产物；
2. 并行优先：能并行就不串行（worktree/多会话）；
3. 干预要快：以"步"为单位响应人的意志；
4. 通信要限：三重熔断 + 账本，防智能体互相放大；
5. 成本要细：五维分摊到单次调用；
6. 质量要自动：模拟用户 eval 做质量门；
7. 历史要用：Fork/Replay/Rollback 让试错可回溯；
8. 配置随仓库走：`.mirasim` 项目级配置；
9. 本机与云端同构：Workbench 免费、Cloud 付费，核心不变。
