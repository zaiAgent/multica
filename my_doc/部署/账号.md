Multica **没有传统的账号+密码，也没有预置的管理员账号**。它用“邮箱 + 验证码”登录，谁第一个注册并创建工作区，谁就是该工作区的 `owner`（最高管理员）。

## 登录流程（make selfhost 之后）

1. 浏览器打开 **http://localhost:3000**；
2. 输入你的邮箱（相当于账号，不用设密码）；
3. 服务端生成验证码，你从下面三种方式之一拿到它并填入，即登录成功。

## 三种获取验证码的方式

| 方式 | 操作 | 适用 |
| --- | --- | --- |
| **推荐（正式用）** | `.env` 配 `RESEND_API_KEY`（Resend 邮件服务），重启后端，验证码发到你邮箱 | 生产/长期使用 |
| **看日志（最省事）** | 不配邮件，验证码直接打印在后端容器日志里： | 本机试用 |
| **固定码** | `.env` 设 `APP_ENV=development` + `MULTICA_DEV_VERIFICATION_CODE=888888`，重启后端，用这个码登录 | 本地/私有测试 |

看日志拿验证码：

```bash
docker compose -f docker-compose.selfhost.yml logs -f backend | grep "Verification code"
# 日志形如：[DEV] Verification code for you@example.com: 123456
```

重启后端（改了 `.env` 后需要）：

```bash
docker compose -f docker-compose.selfhost.yml up -d backend
```

## 管理员从哪来

- **第一个登录并创建工作区的用户自动成为 `owner`**（角色分 `owner` / `admin` / `member`），不存在系统层面单独的“初始管理员账号”；
- 后续成员通过注册登录后加入工作区，由 owner/admin 管理；
- 想控制谁能注册/建工作区，在 `.env` 设 `ALLOW_SIGNUP`、`DISABLE_WORKSPACE_CREATION`、`WORKSPACE_CREATION_ALLOWED_EMAILS`（改完重启后端生效）。

> ⚠️ 安全提醒：`MULTICA_DEV_VERIFICATION_CODE=888888` 绝不能用在公网可达的实例上——任何知道你邮箱的人都能用这个固定码登录你的管理员账号。
