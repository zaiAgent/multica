## 一、Multica 是什么

Multica 是一个源码公开的团队工作区：把任务像派活给同事一样交给 AI 编码智能体——它自己接手、
边做边汇报、卡住了主动说，做完交回来给你审。**自托管**意味着整套系统跑在你自己的基础设施上：
你的机器、你的 Git 服务、你的规矩。

## 二、架构与组件

```
   Web（浏览器）        桌面端（Electron）        iPhone · iPad（Expo）
         │                      │                          │
         ▼                      │                          │
  ┌──────────────┐              │                          │
  │   Next.js    │              │                          │
  │  页面与 API  │              │                          │
  │     代理     │              │                          │
  └──────┬───────┘              │                          │
         ▼                      ▼                          ▼
  ┌───────────────────────────────────────────────────────────┐   ┌───────────────┐
  │                 Go 后端（Chi + WebSocket）                │──>│ PostgreSQL 17 │
  └─────────────────────────────┬─────────────────────────────┘   └───────────────┘
                                │  通过 WebSocket 下发运行
                        ┌───────┴────────┐
                        │    守护进程    │  跑在你的机器上，紧挨着你的代码
                        └───────┬────────┘
                                │  拉起
              ┌─────────────────┴──────────────────┐
              │  Claude Code · Codex · Cursor · …  │
              └────────────────────────────────────┘
```

| 组件 | 说明 | 技术 |
| --- | --- | --- |
| Web 前端 | 网页应用 | Next.js 16（App Router） |
| 后端 | REST API + WebSocket 服务 | Go（单二进制） |
| 数据库 | 主数据存储 | PostgreSQL 17（`pgcrypto` + `pg_trgm`） |
| 智能体运行时 | 本地守护进程拉起受支持的智能体 CLI | `multica` CLI + agent daemon（跑在 Docker 之外的本机） |

服务端三件套（前端/后端/数据库）由 Docker Compose 拉起；**守护进程（daemon）跑在你本机**，
它检测已装的智能体 CLI、向服务端注册，并在任务分配时执行工作。

## 三、前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| Docker + Docker Compose | 必需 | 安装脚本会检查，缺失时给出安装链接 |
| 至少一个智能体 CLI | 必需 | 装好并**登录好**，见第五节运行时表；Multica 负责驱动，但不替你安装 |
| 操作系统 | macOS / Linux / Windows | Windows 走 PowerShell 安装脚本 |

> 唯一的前提：跑智能体的那台机器上，得装好、登录好至少一个受支持的智能体 CLI。

## 四、安装方式

### 方式 A：快速安装（推荐，两条命令搞定）

```bash
# 1. 安装 CLI + 拉起自托管服务端
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash -s -- --with-server

# 2. 配置 CLI、认证、启动守护进程
multica setup self-host
```

安装脚本会：
1. 安装 `multica` CLI；
2. 拉取最新自托管资产；
3. 从 GHCR 拉取官方 Multica 镜像；
4. 按本机（localhost）默认配置好一切。

完成后打开 **http://localhost:3000** 即可使用。

**Windows（PowerShell）等价操作：**

```powershell
# 1. 安装 CLI + 拉起自托管服务端
$env:MULTICA_MODE="with-server"; irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex

# 2. 配置 CLI、认证、启动守护进程
multica setup self-host
```

> 说明：快速安装会从 GHCR 拉取官方镜像，需要 Docker。如果所选 GHCR 标签尚未发布，
> 可在代码目录里跑 `make selfhost-build` 兜底。

### 方式 B：分步安装（手动）

```bash
git clone https://github.com/multica-ai/multica.git
cd multica
make selfhost
```

`make selfhost` 自动完成：从示例创建 `.env`、生成随机 `JWT_SECRET`、用 Docker Compose 启动全部服务。

默认从 GHCR 拉取最新稳定版镜像；想用当前代码构建后端/Web，改跑：

```bash
make selfhost-build
```

（使用本地 `multica-backend:dev` / `multica-web:dev` 标签，不覆盖拉取的 `:latest` 镜像。）

三条 make 命令分别对应什么

| 命令 | 镜像来源 | 你的源码改动 | 用途 |
| --- | --- | --- | --- |
| `make selfhost` | 从 GHCR 拉官方预构建镜像（`:latest`） | **不包含** | 正常部署，官方发什么跑什么 |
| `make selfhost-build` | 从**你当前 checkout** 现场构建 `multica-backend:dev` / `multica-web:dev` | **包含** | 想验证/使用自己改过的代码，但仍要容器化管理 |
| `make dev` | 不做镜像，直接在宿主机起开发服务（热更新、开发数据库等） | 包含且实时生效 | **写代码时**的开发环境，非部署形态 |







两种“跑起来”的方式

```
方式一：拉现成镜像                          方式二：用你的源码现场构建镜像
GHCR 官方仓库 ──pull──> Docker 容器         你的本地源码 ──docker build──> 本地镜像 ──> Docker 容器
（官方编译好的，不含你的改动）               （包含你 checkout 里的所有本地修改）
```

 
**判断一：改了源码不用换部署方式**

假设你改了 `server/` 里的 Go 代码，想让服务跑上你的改动。直觉上你可能觉得“那就得源码安装（手动 go build、node build）了”——不需要。`make selfhost-build` 做的事就是：把你改过的源码打成本地 Docker 镜像（打上 `:dev` 标签，不会覆盖官方拉下来的 `:latest`），然后用同一套 `docker-compose.selfhost.yml` 起栈。你享受的还是容器的好处（一条命令启停、环境隔离、升级回滚方便），只是镜像内容换成了你的代码。

**判断二：它是兜底手段，且 make dev 不是部署**

- 正常情况下 `make selfhost` 拉官方镜像就够了，**没改代码就不该用 selfhost-build**（白白多花构建时间，还可能与官方版本产生偏差）。
- “GHCR 标签未发布”指：官方仓库 `main` 走得很快，你 clone 到的最新代码里，compose 文件引用的镜像 tag 可能还没在 GHCR 上发布过，`make selfhost` 会拉取失败——这时才退回 `make selfhost-build` 自己构建。
- `make dev` 虽然也“用你的源码跑服务”，但它是开发引导：起的是热更新开发服务、开发专用配置，进程形态和自托管生产栈完全不同。用它当部署，等于把开发环境当生产环境跑，不可靠。

一句话总结：**部署的形态永远是容器；镜像的来源才是你选命令的依据——没改代码用 `selfhost`（拉官方镜像），改了代码或官方镜像还没发版用 `selfhost-build`（本地构建镜像），写代码调试才用 `dev`。**


 

启动完成后：

- **前端（Web 界面）**：http://localhost:3000
- **后端 API**：http://localhost:8080


日常运维：

```bash
make selfhost-stop                 # 停止
docker compose -f docker-compose.selfhost.yml pull && \
docker compose -f docker-compose.selfhost.yml up -d   # 升级
```
两个补充判断：

想用本地修改过的源码跑服务：不用切源码安装，仍走容器——make selfhost-build 会从当前 checkout 构建镜像（multica-backend:dev / multica-web:dev）再起栈，兼顾容器化管理和源码改动。
只有 GHCR 标签未发布时才需要兜底 make selfhost-build；make dev 是开发环境引导（起所有服务热更新），不要用于部署。


### 方式 C：手动 Docker Compose（不跑 make）

```bash
git clone https://github.com/multica-ai/multica.git
cd multica
cp .env.example .env
```

编辑 `.env`，**必须设置 `JWT_SECRET`**（docker compose 没有它拒绝启动，生产模式后端
遇到开发默认值或已知占位符会拒绝启动）：

```bash
JWT_SECRET=$(openssl rand -hex 32)
```

然后启动：

```bash
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
```

## 五、登录（Step 2）

打开 http://localhost:3000。Docker 自托管栈默认 `APP_ENV=production`，默认没有固定验证码，
三种登录方式任选其一：

| 方式 | 操作 | 适用 |
| --- | --- | --- |
| **推荐（生产）** | 在 `.env` 配置 `RESEND_API_KEY`，重启后端；验证码以真实邮件发送 | 正式使用 |
| 未配置邮件 | 验证码由服务端生成并打印到后端容器日志（找 `[DEV] Verification code for ...:`） | 单机一次性测试 |
| 固定验证码 | `.env` 设 `APP_ENV=development` + `MULTICA_DEV_VERIFICATION_CODE=888888`，重启后端 | 本地/私有测试 |

```bash
# 查看后端日志中的验证码
docker compose -f docker-compose.selfhost.yml logs -f backend | grep "Verification code"
```

> ⚠️ **安全警告**：公网可达的实例**不要**设置 `MULTICA_DEV_VERIFICATION_CODE`——
> 任何知道邮箱地址的人都能用该固定码登录。

`ALLOW_SIGNUP`、`DISABLE_WORKSPACE_CREATION`、`WORKSPACE_CREATION_ALLOWED_EMAILS`、
`GOOGLE_CLIENT_ID` 修改后同样需重启后端/compose 栈生效；Web UI 运行时从 `/api/config`
读取（无需重建 Web 镜像），其中 `WORKSPACE_CREATION_ALLOWED_EMAILS` 仅后端读取。

## 六、安装 CLI 并启动守护进程（Step 3）

守护进程跑在**本机（Docker 之外）**，检测已装的智能体 CLI、向服务端注册、任务分配时执行工作。
每个想在本机跑智能体的成员都需要：

### a) 安装 CLI 和至少一个智能体 CLI

```bash
# macOS / Linux（已跑过快速安装的可跳过）
brew install multica-ai/tap/multica
```

**受支持的智能体 CLI（26 种）**——装好并登录，命令需在 PATH 上：

| Provider | CLI 命令 | Provider | CLI 命令 |
| --- | --- | --- | --- |
| Claude Code | `claude` | OpenAI Codex | `codex` |
| Cursor Agent | `cursor-agent` | GitHub Copilot CLI | `copilot` |
| OpenCode | `opencode` | OpenClaw | `openclaw` |
| Hermes | `hermes` | Pi | `pi` |
| Antigravity | `agy` | CodeBuddy | `codebuddy` |
| DevEco Code | `deveco` | Grok | `grok` |
| Kimi | `kimi` | Kiro CLI | `kiro-cli` |
| Qoder CLI | `qodercli` | Qoder CN | `qoderclicn` |
| Qwen Code | `qwen` | QwenPaw | `qwenpaw` |
| Reasonix | `reasonix` | Trae CLI | `traecli` |
| DeepSeek Harness | `dsh` | Oh-My-Pi | `omp` |
| MiniMax Code | `mcode` | Dim | `dim` |
| 华为云 CodeArts | `codearts` | ZeroClaw | `zeroclaw` |

### b) 一条命令完成配置与启动

```bash
multica setup self-host
```

自动完成：
1. 配置 CLI 连接 `localhost`（端口 8080/3000）；
2. 打开浏览器认证；
3. 发现你的工作区；
4. 后台启动守护进程。

**自定义域名（内网/生产部署）：**

```bash
multica setup self-host --server-url https://api.example.com --app-url https://app.example.com
```

**手动逐步配置（替代 multica setup）：**

```bash
multica config set server_url http://localhost:8080
multica config set app_url http://localhost:3000
multica login          # 打开浏览器登录
multica daemon start   # 启动守护进程
```

**验证守护进程状态：**

```bash
multica daemon status
```

## 七、验证并开始使用（Step 4，五分钟跑通第一个智能体）

1. 打开 Web 工作区 http://localhost:3000；
2. 进入 **设置 → 运行时（Runtimes）**——应能看到你的机器（用桌面端接入则是自动注册，
   并顺便检测已装 CLI；再接一台机器则打开 **团队 → 运行时 → 添加运行时 → 其他机器或服务器**，
   把弹窗里的两条命令粘到那台机器的终端）；
3. 进入 **设置 → 智能体（Agents）**，点侧边栏 **团队** 里的 **+（新建智能体）**：选中运行时、
   选提供方、起名字（也可选**通过 AI 创建**，描述几句自动生成配置）；
4. 建一个任务（Issue），负责人选成这个智能体——它会自动接手、在你的机器上跑、边做边评论，
   干完把任务挪到**审核中**。

日常使用要点：

- **执行日志**：每次工具调用、命令和报错都带时间戳，可完整回放；
- **运行中插话**：智能体干活时直接回复，消息进当前运行（支持 Claude Code、Codex、Grok、Kiro）；
- **人来验收**：产出先进"审核中"，不直接进 main，上不上线你说了算；
- **收件箱**：只在智能体需要你拍板时提醒；
- **重试与超时**：失败的运行会自动重试，或停下来告诉你原因。

## 八、升级 / 停止 / 卸载

### 升级

```bash
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
```

- 想锁定特定版本：在 `.env` 设 `MULTICA_IMAGE_TAG=v0.2.4` 这样的确切版本号；
- 数据库迁移在后端启动时自动执行；
- 所选 GHCR 标签未发布时，兜底跑 `make selfhost-build` 或
  `docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml up -d --build`。

### 停止

```bash
# 安装脚本方式停止整套服务
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash -s -- --stop

# 手动 clone 方式
make selfhost-stop      # 停 Docker Compose 服务（后端/前端/数据库）
multica daemon stop     # 停本机守护进程
```

### 切换到 Multica 云端

```bash
multica setup   # 重新配置到 multica.ai、重新认证、重启守护进程（覆盖前会提示）
```

本地 Docker 服务不受影响，不需要时单独停止。

## 九、匿名遥测（了解即可，可关闭）

自托管服务端每个 UTC 日向固定端点发送**一份部署级匿名快照**：只有版本号和分桶计数
（工作区数、成员数、活跃智能体/守护进程数、运行量等），**不含**名称、内容、IP、业务 ID、
提示词或任何标识符；不用于计费、许可、认证或安全决策。

关闭方式：在 API 服务端设 `DO_NOT_TRACK=1`（或 `true`）后重建/重启后端。
（`ANALYTICS_DISABLED` 只控制另一套 PostHog 集成，关闭不了这套第一方遥测。）

## 十一、本机快速上手速查（TL;DR）

```bash
# 0. 前提：Docker 已装；至少一个智能体 CLI 已装且已登录（如 claude / codex）

# 1. 一键安装（CLI + 服务端）

make selfhost-stop && multica daemon stop             # 停止
```
