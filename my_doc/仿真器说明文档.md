## 2. 总体架构与真值机制

### 2.1 三层架构

```
┌────────────────────────────────────────────────────────────┐
│  Python 客户端（pip install airsim）                        │
│  moveToGPSAsync / getGpsData / simGetImages / 录制脚本 …    │
└──────────────────────┬─────────────────────────────────────┘
                       │ msgpack-RPC（默认 TCP 41451，本机或跨机）
┌──────────────────────▼─────────────────────────────────────┐
│  Colosseum 仿真层（AirLib + simple_flight / PX4 SITL）      │
│  飞行物理、传感器仿真（GPS/IMU/磁力计/气压计）、相机渲染调度 │
└──────────────────────┬─────────────────────────────────────┘
                       │ 引擎插件（Unreal/Plugins/Colosseum）
┌──────────────────────▼─────────────────────────────────────┐
│  Unreal Engine 5 渲染层（BlocksV2 等工程）                   │
│  + Cesium for Unreal 插件：流式加载真实地球 3D Tiles        │
│  + CesiumGeoreference：把 UE 世界原点锚定到真实经纬度        │
└────────────────────────────────────────────────────────────┘
```

### 2.2 坐标系与经纬度真值的产生机制

- 所有 AirSim/Colosseum API 使用 **NED 坐标系**：+X 北、+Y 东、+Z 下，SI 单位（米、弧度），载具起始位置即 NED 原点 (0,0,0)。
- settings.json 的 **`OriginGeopoint`** 定义 UE 场景中 **PlayerStart 组件所在点的经纬度与高度**（官方 Settings 文档原文），载具 home 点由此换算。
- 由此形成完整换算链：

```
UE 世界坐标(米) ──以 PlayerStart 为参考──▶ NED 坐标 ──OriginGeopoint──▶ WGS-84 经纬度/高度
```

**与 Cesium 场景对齐的"三个一致"（本方案核心配置）**：

1. 场景中 `CesiumGeoreference` 的 Origin Latitude / Longitude / Height = 目标区域坐标 (LAT0, LON0, H0)；
2. `PlayerStart` 放在 CesiumGeoreference 原点附近，即 UE 世界坐标约 (0, 0, 0)；
3. settings.json 的 `OriginGeopoint` = (LAT0, LON0, H0)。

三者一致后，`getGpsData()` 返回的经纬度/高度即与画面中的真实地物一一对应。

**换算示例**（线性近似，便于理解量级；AirSim 内部使用 WGS-84 精确换算）：设原点 (40.0°N, 116.2°E, 50 m)，无人机飞到 NED (1000, 2000, -3000)，即北向 1 km、东向 2 km、爬升 3 km：

| 项 | 计算 | 结果 |
|---|---|---|
| 纬度 | 40.0 + 1000 / 111320 | ≈ 40.00898° |
| 经度 | 116.2 + 2000 / (111320 × cos40°) | ≈ 116.22345° |
| GPS 高度 | 50 + 3000 | ≈ 3050 m |

也就是说，`moveToZAsync(-3000)` 后从 `getGpsData()` 读到的经纬度变化会严格落在这些真值上，可直接作为算法评测的 ground truth。

**高度语义说明**（易混淆，务必阅读）：

- **相对高度** = −z_NED（z 为负表示在空中）。需求中的"飞行高度 3000 m+"通常指此项；
- `getGpsData().gnss.geo_point.altitude` ≈ OriginGeopoint.Altitude + 相对高度；
- Cesium 内部使用椭球高，与海拔（正高）存在米级大地水准面差距。对跟踪/识别类算法测试无影响；如有严格海拔需求，可查询目标区域 geoid 修正值后在导出数据时补偿。

### 2.3 3000 m+ 高度可行性

| 关注点 | 结论 |
|---|---|
| 数值精度 | UE5 引入大世界坐标（LWC，厘米级双精度表示），千米级高度与数十公里水平范围无可见抖动 |
| 场景内容 | Cesium 全球地形支持任意高度；高空时瓦片自动加载较粗 LOD 层级，属正常现象 |
| 飞控 | simple_flight 无高度硬限制；`moveToZAsync(-3000, 8)` 以 8 m/s 爬升约 6~7 分钟；批量采数可先用 `simSetVehiclePose` 直接传送到位 |
| 时钟 | settings.json 的 `ClockSpeed` 可设大于 1 加速仿真时钟以缩短等待（注意物理仿真质量会下降） |

## 4. 部署步骤（Windows 主力机）

### 4.1 安装 UE 与 Visual Studio

1. 安装 Epic Games Launcher → 左侧 Unreal Engine 标签 → Install 下载 **UE ≥ 5.0（建议 5.3）**；安装后在 Launch 按钮旁的下拉箭头确认该版本已被设为 `current`。
2. 安装 **Visual Studio 2022**，安装时勾选：
   - Desktop development with C++（使用 C++ 的桌面开发）
   - Windows 10 SDK 10.0.19041（默认已选）
   - Individual Components 中的最新 .NET Framework SDK
   - （建议追加）Game development with C++（使用 C++ 的游戏开发）工作负载

### 4.2 编译 Colosseum

打开 **Developer Command Prompt for VS 2022**（开始菜单搜索），执行：

```bat
D:
git clone https://github.com/CodexLabsLLC/Colosseum.git
cd Colosseum
build.cmd
```

注意事项：

- 官方文档明确不建议把仓库放在 C 盘（脚本可能失败且需管理员权限），建议放 D/E 盘；
- 路径中不要有中文与空格；
- 首次编译约 20~60 分钟，取决于 CPU 与磁盘。

### 4.3 打开 BlocksV2 工程并验证插件

1. 编译完成后重启 Epic Launcher 与 UE；如弹出 ".uproject 关联" 提示，点 **fix now**。
2. 双击 `Colosseum\Unreal\Environments\BlocksV2\BlocksV2.sln` 用 VS 打开：将 Blocks 设为 Start Up Project，Build 配置选 **Development Editor + x64**，F5 启动（或直接双击 `BlocksV2.uproject` 用编辑器打开）。
3. UE 编辑器加载完成后按 **Play**。若 settings.json 未指定 SimMode 会弹窗选择 Multirotor/Car；选 Multirotor 出现无人机即表示 Colosseum 插件工作正常（此时还是默认积木场景）。

### 4.4 安装 Cesium 插件并接入真实卫星地图

1. 在 Epic 商店 / Fab 中搜索 **Cesium for Unreal**（免费插件），安装到 BlocksV2 工程；然后在 UE 编辑器 Edit → Plugins 中确认已启用（启用后需重启编辑器）。
2. 菜单 **Window → Cesium** 打开 Cesium 面板，点击 **Sign In** 连接 Cesium ion 账号（跳转浏览器授权；允许后面板会列出该账号可用的资产）。
3. 在面板的 **Quick Add Cesium ion Assets** 区域，依次点击添加：
   - **Cesium World Terrain** —— 全球地形 + 卫星影像底图，任意区域可用；
   - **Google Photorealistic 3D Tiles** —— Google 摄影测量三维城市，视觉最真实；
   - （可选）**Cesium OSM Buildings** —— 全球城市建筑白模，城市场景做遮挡/参考时有用。
   添加后场景中会自动创建 `Cesium3DTileset` 与 `CesiumGeoreference` Actor，视口中即可看到真实地球。
4. 选中 `CesiumGeoreference`，在 Details 面板把 **Origin Latitude / Origin Longitude / Origin Height** 设为目标区域坐标，例如 `40.0 / 116.2 / 50`（Height 填该点地面大致高程，单位米）。
5. 把场景中原有的 **PlayerStart** 拖到 CesiumGeoreference 原点上方：在 Details 面板把 Location 直接改为 `X=0, Y=0, Z=100`。注意 **UE 世界单位是厘米**，Z=100 即原点上方 1 m；若穿地可加大（如 Z=5000 为 50 m）。
6. 视口预览：按住鼠标右键 + W/A/S/D 移动（Q/E 下降/上升），飞到地形上方确认瓦片正常加载。

### 4.5 对齐真值坐标（关键一步）

编辑 `C:\Users\<用户名>\Documents\AirSim\settings.json`（首次 Play 后自动生成）：

```json
{
  "SettingsVersion": 1.2,
  "SimMode": "Multirotor",
  "OriginGeopoint": {
    "Latitude": 40.0,
    "Longitude": 116.2,
    "Altitude": 50
  }
}
```

数值必须与 4.4 节第 4 小步的 CesiumGeoreference 完全一致。重新 Play 后，用第 6 章脚本读取 `getGpsData()`，返回 40.0/116.2 附近坐标即对齐成功。

### 4.6 部署自检清单

按顺序逐项确认，全部通过即环境就绪：

- [ ] UE 编辑器打开 BlocksV2 按 Play 不报错，无人机正常生成；
- [ ] 视口中可见 Cesium 真实地形/城市（而不是只有默认积木场景）；
- [ ] Python 侧 `confirmConnection()` 连接成功；
- [ ] `getHomeGeoPoint()` 返回 CesiumGeoreference 设定的经纬度；
- [ ] 运行 6.2 节最小脚本，无人机起飞后 `getGpsData()` 的经纬度随飞行连续变化、高度随爬升增加。

## 6. 基础操作与真值获取（simple_flight 链路）

### 6.1 完整 settings.json（1080p 相机 + GPS 原点）

```json
{
  "SettingsVersion": 1.2,
  "SimMode": "Multirotor",
  "ViewMode": "Fpv",
  "OriginGeopoint": {
    "Latitude": 40.0,
    "Longitude": 116.2,
    "Altitude": 50
  },
  "CameraDefaults": {
    "CaptureSettings": [
      {
        "ImageType": 0,
        "Width": 1920,
        "Height": 1080,
        "FOV_Degrees": 90,
        "AutoExposureSpeed": 100,
        "MotionBlurAmount": 0,
        "TargetGamma": 1.0
      }
    ]
  },
  "Vehicles": {
    "Drone1": {
      "VehicleType": "SimpleFlight",
      "AutoCreate": true,
      "Cameras": {
        "front_center": {
          "CaptureSettings": [
            { "ImageType": 0, "Width": 1920, "Height": 1080, "FOV_Degrees": 90 }
          ],
          "X": 0.5, "Y": 0.0, "Z": 0.0,
          "Pitch": 0.0, "Roll": 0.0, "Yaw": 0.0
        }
      }
    }
  }
}
```

要点说明：

- `ViewMode: "Fpv"`：主窗口直接显示机头第一视角；批量采数时可改为 `"NoDisplay"` 关闭主屏渲染、只保留 API 取流，提高帧率。
- 相机 X/Y/Z 是相对机体的 NED 偏移（X 前、Y 右、Z 下，单位米），此处机头前方 0.5 m。
- `MotionBlurAmount: 0` 与 `TargetGamma: 1.0`：输出面向视觉算法的"干净"图像。
- 多机仿真：`Vehicles` 下并列添加多台即可，API 调用时传 `vehicle_name` 区分。

### 6.4 3000 m 高空任务完整脚本（起飞→爬升→GPS 巡航→云台俯仰→取流+真值 CSV）

```python
# high_altitude_mission.py
# 前置：UE 场景已按第 4 章接入 Cesium；settings.json 已配置 1080p 相机与 OriginGeopoint
import airsim, os, csv, time

OUT = "D:/airsim_out"            # Linux 改为 ~/airsim_out
os.makedirs(OUT, exist_ok=True)

client = airsim.MultirotorClient()
client.confirmConnection()
client.enableApiControl(True)
client.armDisarm(True)

# 1) 起飞并爬升到 3000 m 相对高度（NED z=-3000 表示向上 3000 m；速率 8 m/s，约 6~7 分钟）
client.takeoffAsync().join()
client.moveToZAsync(-3000, 8).join()

# 2) 巡航到目标经纬度：参数为 纬度、经度、高度、水平速度(m/s)
#    注意：此处高度是相对 OriginGeopoint.Altitude 的高度差
client.moveToGPSAsync(40.05, 116.25, 3000, 12).join()

# 3) 相机云台俯仰：下视 45°（pitch 单位弧度；NED 航空约定下"下视"为负）
client.simSetCameraPose(
    "front_center",
    airsim.Pose(airsim.Vector3r(0, 0, 0),              # 相对安装位置保持不变
                airsim.to_quaternion(-0.785, 0, 0)))    # pitch = -45°

# 4) 边巡航边采集：第一视角 PNG 序列 + 真值 CSV
with open(os.path.join(OUT, "truth.csv"), "w", newline="") as f:
    w = csv.writer(f)
    w.writerow(["frame", "unix_t", "lat", "lon", "alt",
                "x_ned", "y_ned", "z_ned", "roll", "pitch", "yaw"])
    for i in range(300):                                # 约 30 s @ 10 Hz
        gp = client.getGpsData().gnss.geo_point
        k = client.simGetGroundTruthKinematics()
        r, p, y = airsim.to_eularian_angles(k.orientation)
        w.writerow([i, time.time(), gp.latitude, gp.longitude, gp.altitude,
                    k.position.x_val, k.position.y_val, k.position.z_val, r, p, y])
        img = client.simGetImages(
            [airsim.ImageRequest("front_center", airsim.ImageType.Scene, False, True)],
            vehicle_name="Drone1")[0]                   # 多机时用 vehicle_name 区分
        airsim.write_file(os.path.join(OUT, f"frame_{i:05d}.png"),
                          img.image_data_uint8)
        time.sleep(0.1)

client.landAsync().join()
client.armDisarm(False)
print("采集完成，输出目录：", OUT)
```

实用技巧：

- **快速布置机位（跳过爬升等待）**：
  `client.simSetVehiclePose(airsim.Pose(airsim.Vector3r(0, 0, -3000), airsim.to_quaternion(0, 0, 0)), True)`
  直接把无人机瞬移到 3000 m 高度（NED z=-3000），适合批量采数时快速复位。
- **内置录像**：settings.json 加 `"Recording": {"RecordInterval": 0.05, "Cameras": [{"CameraName": "front_center", "ImageType": 0, "PixelsAsFloat": false, "Compress": true}]}`，仿真中按 **R** 键开始/停止，图像与运动学数据（tsv）自动存入 `Documents\AirSim\` 下带时间戳的子目录。
- **版本兼容**：若所用版本没有 `moveToGPSAsync`，用 `moveToPositionAsync(x, y, z, v)`（NED 米制）等价替代，经纬度与 NED 的换算依据 OriginGeopoint。

### 6.5 帧率与画质建议（RTX 独显）

- Epic 画质 + 1920×1080 取流：RTX 3060 级别可稳定 30 fps 以上；
- 采数优先流畅度：降到 1280×720 + Low 画质，或 `"ViewMode": "NoDisplay"`；
- Cesium 瓦片为流式加载，首次飞入新区域有数秒逐渐清晰的过程；正式采数前先预飞一遍让瓦片缓存。

## 8. 常见问题与故障排查（FAQ）

| # | 现象 | 可能原因 | 解决方法 |
|---|---|---|---|
| 1 | `confirmConnection` 一直连不上 | UE 未按 Play；`ApiServerPort` 被改过；防火墙拦截 | 确认仿真处于运行状态；核对 settings.json 端口（默认 41451）；放行 TCP 41451 |
| 2 | GPS 返回 47.64 / -122.14（西雅图附近） | `OriginGeopoint` 未生效 | 检查 `Documents/AirSim/settings.json` 是否保存正确；重新 Play 生效 |
| 3 | Cesium 地球黑屏 / 瓦片不加载 | ion 未登录；免费配额用尽；网络不可达 | Cesium 面板重新 Sign In；登录 cesium.com/ion 查看用量；检查网络连通性 |
| 4 | 3000 m 高空画面模糊 | 瓦片 LOD 层级较粗（正常）或仍在加载 | 等待数秒；需要更清晰时调小 Cesium3DTileset 的 Maximum Screen Space Error（更精细也更耗资源） |
| 5 | 取流帧率低 | 分辨率/画质过高；主屏渲染抢占资源 | 降至 720p + Low；`"ViewMode": "NoDisplay"`；关闭多余视口 |
| 6 | `build.cmd` 报错 | VS 组件不全；路径含中文/空格；仓库在 C 盘 | 按 4.1 节补装组件；仓库移到 D 盘纯英文路径后重试 |
| 7 | Linux 编译失败 | clang/cmake 版本不符；磁盘或内存不足 | 重跑 `./setup.sh`；确认磁盘 ≥ 100 GB、内存 ≥ 16 GB |
| 8 | `pip install airsim` 失败 | Python 版本过新（老包在构建期导入 numpy） | 用 Python 3.9/3.10 建虚拟环境（conda/venv）后安装 |
| 9 | PX4 一直显示 Waiting for simulator | 防火墙；端口配置不一致；WSL2 未设宿主机 IP | 放行 TCP 4560 / UDP 14540；核对 7.2 节配置；设置 `PX4_SIM_HOST_ADDR` |
| 10 | 画面地物与真值高度差几米到十几米 | 椭球高与海拔高的 geoid 差异；CesiumGeoreference 高度基准不一致 | 两端使用同一高度基准即可；严格海拔需求见 2.2 节说明 |
| 11 | Play 后无人机直接坠落/穿地 | 出生点位于 Cesium 地形之下 | 抬高 PlayerStart 的 Location Z（UE 单位厘米，如 5000 = 50 m） |

### 附录 B：离线瓦片方案（内网 / 无外网环境）

在线流式（Cesium ion）依赖外网。内网环境可改用本地 3D Tiles（以下为方案概览，具体以所用工具的官方文档为准）：

1. **数据准备**：目标区域的卫星影像（GeoTIFF/IMG）与 DEM 高程数据；
2. **切片**：用 CesiumLab（免费、中文界面）等工具将影像与高程处理为 3D Tiles（输出 tileset.json + 瓦片文件）；
3. **本地服务**：用 nginx 或任意静态 HTTP 服务托管切片目录；
4. **UE 接入**：场景中添加 `Cesium3DTileset`，Source 选 **From Url**，填 `http://<内网IP>:<端口>/tileset.json`；
5. **替代路线**：把切片成果上传为 Cesium ion 私有资产后再 Quick Add——部署更简单，但运行时仍从 ion 云端拉流，并非完全离线。
